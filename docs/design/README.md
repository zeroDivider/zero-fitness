# Design References

Store design material used to build and review the app here.

## Structure

- `mockups/` — standalone HTML screen and flow mockups
- `assets/` — images or other files shared by mockups, when needed

## Conventions

- Name files by feature or flow, for example `exercise-library.html`.
- Include important UI states in the filename when they are separate, such as `exercise-library-empty.html`.
- Prefer self-contained HTML. Put shared external files under `assets/` and use relative paths.
- Treat mockups as visual and behavioral references; application models and requirements remain authoritative.
- Mention the exact mockup path and screen label when requesting implementation or review.
